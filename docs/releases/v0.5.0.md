# Release Notes v0.5.0

Review-aware tools: read a Google Doc's suggested edits and any file's comments, and, only if you turn it on, upload and update files. Every Google call now goes through gogoogle, and tool authorization is deny-by-default.

## Highlights

- **Suggested edits**: `get_document_suggestions` splits a Doc into original, inserted, and deleted text, with each block's text before and after the suggestions
- **Comments**: a new Drive skill's `get_file_comments` returns comments with quoted text, resolved state, and replies, for Docs, Sheets, Slides, and any other file
- **Opt-in publishing**: `upload_file` and `update_file` exist only with `--enable-write`, read local files only from `--upload-root`, and are audit-logged
- **Deny by default**: every tool has exactly one required scope, and an unmapped tool is denied when a token carries a scope claim
- **One path to Google**: the skills use only gogoogle, enforced by a test

## Authorization change

!!! warning "Scoped-token deployments: add the new scopes"
    This release adds the `drive:read` and `drive:write` policy scopes.

    - `get_file_comments` needs `drive:read`.
    - `upload_file` and `update_file` need `drive:write`, and exist only in write mode.
    - `get_document_suggestions` needs `docs:read`, like the other Docs tools.

    A deployment that issues tokens with a `scope` claim must add these scopes
    before callers can use the new tools; until then those calls are denied with
    an `access denied` message naming the missing scope. Existing tools and
    tokens without a `scope` claim are unaffected. Authorization now uses an exact
    tool-to-scope table, so any tool that is not in the table is denied for a
    scoped token. See [HTTP Transport & ID-JAG](../configuration/http-transport.md#scopes).

## New Features

### Suggested edits

```json
{ "name": "get_document_suggestions", "arguments": { "document_id": "1BxiMVs0XRA5nFMdKvBdBZjgmUUqptlbs74OgvE2upms" } }
```

Each paragraph and table cell is a block with `original`, `insertion`, and `deletion` segments in document order, and the block's `original` and `accepted` text. The Docs API does not report who made a suggestion, so blocks carry no author. See [Google Docs tools](../tools/docs.md#get_document_suggestions).

### Comments

```json
{ "name": "get_file_comments", "arguments": { "file_id": "1BxiMVs0XRA5nFMdKvBdBZjgmUUqptlbs74OgvE2upms" } }
```

Returns `{ "file_id": ..., "comments": [...] }`. Every page is returned, or an error. Author email addresses appear only when Google returns them; treat them as personal data. See [Google Drive tools](../tools/drive.md#get_file_comments).

### Write mode

Off by default. Turn it on with a flag or environment variable:

```bash
mcp-google serve --enable-write --upload-root ./to-publish
```

| Flag | Environment variable | Description |
|------|----------------------|-------------|
| `--enable-write` | `MCP_GOOGLE_ENABLE_WRITE=true` | Register `upload_file` and `update_file`. A service account file also requests the `drive.file` Google scope. A flag given on the command line, including `--enable-write=false`, wins over the variable |
| `--upload-root` | `MCP_GOOGLE_UPLOAD_ROOT` | The directory local files are read from (default: the working directory) |

- **Narrow scope.** Write mode adds only `drive.file`, which covers just the files the app creates or opens. Without `--enable-write` the server still requests only read-only Google scopes.
- **Confined paths.** A path with `..`, a rooted or drive path outside the root, or a symbolic link that leaves the root is refused as `path_outside_root` before anything is sent to Google, the same way on every platform. A symbolic link with an absolute target is refused even when it points back into the root.
- **One open.** The file is opened once, through the operating system's confined open, and that handle is checked and streamed to Drive, so a link swapped in at the path afterwards is never followed. Files over 50 MB are refused, and a file that grows past the limit while it is being sent is cut off and refused as `file_too_large`.
- **Strict arguments.** A parameter of the wrong type is refused as `invalid_request` instead of being read as empty, so a numeric `folder_id` cannot put the file in the Drive root. File links are accepted only on `drive.google.com` and `docs.google.com`.
- **Conversion.** `convert_to` turns `.docx`, `.odt`, `.txt`, or `.html` into a Google Doc, `.csv`, `.xlsx`, or `.ods` into a Sheet, and `.pptx` or `.odp` into Slides.
- **Structured errors.** Failures return `{"code": ..., "message": ...}`: `path_outside_root`, `not_found`, `permission_denied`, `unsupported_conversion`, `file_too_large`, `invalid_request`, `write_disabled`, or `api_error`.
- **Audit.** Every write call is logged with the caller, tool, file name, and resulting file ID or failure code.

New CLI commands: `get-document-suggestions`, `get-file-comments`, `upload-file`, and `update-file`. The last two refuse to run without `--enable-write`.

## Changed

- The Docs, Sheets, and Slides skills no longer build Google API clients or finish API requests; they call gogoogle. A test fails if a skill imports `google.golang.org/api/option`, builds an API service, or calls `.Do()`.
- Tool authorization is a literal table keyed by exact tool name instead of substring matching.
- The server now advertises 16 tools by default and 18 in write mode.

## Installation

```bash
go install github.com/plexusone/mcp-google/cmd/mcp-google@v0.5.0
```

## Compatibility

Existing tool names, inputs, and outputs are unchanged. The only behaviour change is the authorization change above, which affects only tokens that carry a `scope` claim.
